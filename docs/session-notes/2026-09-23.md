substantial improvement over eSpeak and the diagnostic tone. The remaining

- incorrect tonality in some spans; and

## Completed long-form result

The reconnect-safe browser flow successfully completed all 9 chunks. The job
automatically corrected the pasted text, generated each chunk serially, joined
them into one WAV, and exposed playback/download after completion. The browser
could poll and reconnect rather than holding one long POST request open.

The run also confirmed the throughput limitation: the 0.9B neural model used
roughly eight CPU cores and about 3.2 GB container memory. CPU inference is
functional but too slow for book-length PDF conversion without a faster
backend.

## Hardware conclusion

The laptop has `AMD Radeon(TM) Pro Graphics` with approximately 4 GB reported
adapter memory. It does not have an NVIDIA CUDA device. The current CPU PyTorch
image and provider only use CUDA for acceleration, so the AMD adapter is not
used. A DirectML, AMD-compatible ONNX, or suitable ROCm experiment remains
separate research; compatibility must be demonstrated rather than assumed.

## PDF-to-audio direction

The next product goal is whole-PDF conversion. The documented staged plan is in
`docs/research/pdf-to-audio.md`:

1. bounded upload and Unicode text extraction with pypdf;
2. automatic repair plus page-by-page preview;
3. SQLite-backed durable document and chunk jobs;
4. page/chapter speech with persisted intermediate audio;
5. pypdfium2 rendering plus Tesseract OCR for scanned pages; and
6. chapter WAV/ZIP first, followed by a compressed audiobook format after
   codec licensing review.

Durable jobs must precede multi-hour PDF synthesis because the current
in-memory speech jobs are lost on container restart.

## Exact restart procedure

1. Read this note and check `git status --short --branch`.
2. Start Docker Desktop if it is not already running.
3. Run `docker compose up -d bhashavox` from the repository root.
4. Wait for `docker compose ps bhashavox` to report healthy.
5. Open `http://127.0.0.1:8000` on the laptop. Recheck `ipconfig` before using
   the LAN URL because the previous address `192.168.1.8` can change.
6. Expect the first request after restart to reload the cached model into RAM;
   it should not download the checkpoint again.

## Rename continuation — 2026-09-23

The project was renamed from BhashaVox after discovering an active commercial
product at `bhashavox.com` with overlapping Indian-language text-to-speech and
document features. The replacement name is **Dravidic TTS**. The naming record
and collision screen are in `docs/adr/0002-rename-to-dravidic-tts.md`; that
screen is not a legal or trademark clearance.

The rename is complete across the user interface, Python distribution and
package, Compose service and image, environment variables, API response
headers, download filename, browser storage key, tests, and current
documentation. Historical dated notes retain the old name so they remain an
accurate record. The Docker volume is intentionally still named `hf-cache`, so
the downloaded model is preserved.

New identifiers:

- product: `Dravidic TTS`;
- distribution, CLI, Compose service, and image: `dravidic-tts`;
- Python package: `dravidic_tts`;
- environment prefix: `DRAVIDIC_TTS_`; and
- API response-header prefix: `X-Dravidic-TTS-`.
