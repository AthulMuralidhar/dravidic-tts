Indic Parler runtime`).

## What was completed

- The eSpeak evaluation was rejected because its Malayalam output was robotic
  and often unintelligible. It is not an acceptable user-facing provider.
- Pasted Malayalam now passes through a correction function inside the server
  before synthesis. Users do not need to press a separate cleanup button.
- The function preserves valid Malayalam, repairs detached pre-base vowel signs,
  restores the two known placeholder patterns from the test sample
  (`രാ?തി` -> `രാത്രി` and `ഇ?ത` -> `ഇത്ര`), and removes other Malayalam-adjacent
  question-mark placeholders rather than sending them to speech.
- Both the text-review endpoint and speech endpoint expose whether correction
  occurred. Only the repaired string reaches the speech provider.
- An AI4Bharat Indic Parler-TTS provider was added with recommended English,
  Tamil, and Malayalam voices and natural-language pace descriptions.
- `Dockerfile.neural` and Compose configuration now define a CPU neural runtime,
  a persistent Hugging Face cache, and an interactive `hf-login` setup service.
- Credentials are not stored in the repository, Compose file, image metadata,
  or this note.

## Important limitations at the stopping point

- The neural Docker image has **not** been built. Its pinned dependency graph
  and native libraries still need an actual build test.
- The 3.75 GB gated model has **not** been downloaded or loaded. CPU latency and
  memory use have not been benchmarked.
- The screenshot confirmed that the correct Hugging Face model page was open,
  but did not conclusively establish that the account accepted the gated-access
  conditions.
- Automatic missing-letter restoration is not yet general Malayalam language
  correction. Two observed corruptions have semantic rules; an unknown `?`
  beside Malayalam is removed as a speech-safe fallback. A dictionary or
  language-model restorer is still required for reliable arbitrary corruption.
- Long-form neural synthesis needs chunking and end-to-end testing before the
  original long sample is used.

## Exact restart plan

Start by reading this note and checking `git status --short --branch`. Then:

1. Confirm the Hugging Face account can access the files under
   `ai4bharat/indic-parler-tts`.
2. Build the image with `docker compose build bhashavox`; fix and commit any
   dependency issue before proceeding.
3. Run `docker compose --profile setup run --rm hf-login` in the laptop terminal
   and enter a Hugging Face read token there. Never paste the token into chat.
4. Start with `docker compose up -d bhashavox` and inspect health/logs. The first
   real synthesis will populate the named `hf-cache` volume and can take time.
5. Test one short, clean Malayalam sentence first. Record load time, generation
   time, memory, pronunciation, voice, and output size in `docs/research/`.
6. Add neural-safe sentence chunking, then test the corrected long sample.
7. Replace the small placeholder rule map with an automatic Malayalam lexical
   or model-based restorer and add corpus-backed tests.

Every logical change must continue to end in its own Git commit.
