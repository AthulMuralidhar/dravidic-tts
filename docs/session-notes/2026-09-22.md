# Session handoff — 2026-09-22

## Current status

The neural BhashaVox service is running through Docker Compose and is reachable
from the host at `http://127.0.0.1:8000` and, while the current Wi-Fi address is
unchanged, from the LAN at `http://192.168.1.8:8000`.

The official gated model is downloaded in the Docker `hf-cache` volume and two
short Malayalam requests using the Anjali voice completed successfully. The
working tree was clean before this measurement note was added.

## What was completed

- The eSpeak evaluation was rejected because its Malayalam output was robotic
  and often unintelligible. It is not an acceptable user-facing provider.
- Pasted Malayalam now passes through a correction function inside the server
  before synthesis. Users do not need to press a separate cleanup button.
- The function preserves valid Malayalam, repairs detached pre-base vowel signs,
  restores the two known placeholder patterns from the test sample
  (`രാ?തി` -> `രാത്രി` and `ഇ?ത` -> `ഇത്ര`), and removes other Malayalam-adjacent
  question-mark placeholders rather than sending them to speech.
- Both the text-review endpoint and speech endpoint expose whether correction
  occurred. Only the repaired string reaches the speech provider.
- An AI4Bharat Indic Parler-TTS provider was added with recommended English,
  Tamil, and Malayalam voices and natural-language pace descriptions.
- `Dockerfile.neural` and Compose configuration now define a CPU neural runtime,
  a persistent Hugging Face cache, and an interactive `hf-login` setup service.
- Credentials are not stored in the repository, Compose file, image metadata,
  or this note.
- Browser generation now creates a background job and polls it instead of
  holding one long HTTP request open. The active job ID is retained in browser
  storage, so a refresh or temporary Wi-Fi interruption does not discard the
  result.
- Long script segments are split at sentence or word boundaries into chunks of
  at most 240 characters. The UI reports chunk progress and joins the generated
  WAV chunks into one file.

## Important limitations at the stopping point

- The CPU-only neural image is built and verified. The new chunked long-form
  path is deployed but still awaits a complete listening test.
- Cold setup plus first synthesis took 451.3 seconds. A warm short Malayalam
  synthesis still took 41.9 seconds, so the UI needs progress and queue state.
- Audio quality and pronunciation have not yet been accepted by the user; the
  successful experiment only proves that a valid neural WAV was generated.
- Automatic missing-letter restoration is not yet general Malayalam language
  correction. Two observed corruptions have semantic rules; an unknown `?`
  beside Malayalam is removed as a speech-safe fallback. A dictionary or
  language-model restorer is still required for reliable arbitrary corruption.
- Jobs and completed audio are currently held in memory and are lost when the
  container restarts. This is suitable for one local process, not yet for a
  multi-replica deployment.
