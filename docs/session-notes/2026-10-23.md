# Session handoff — 2026-10-23

## Session goal

Convert the repository's test PDF into restart-safe Malayalam speech parts,
persist every part to disk, and expose completed audio on the local network so
it can be played from a phone.

## Source validation

The source is `test-pdfs/Nishayude_Ponnumon_Kambi_Novel.pdf`: 83 pages and
733,760 bytes. Its embedded text is not usable for speech because many
Malayalam glyphs map to NUL or Unicode noncharacters. PDFium rendering plus
Tesseract `mal+eng` OCR at 300 DPI is therefore mandatory. Automatic page
layout mode (`--psm 3`) produced materially cleaner page-one text than assuming
one uniform block (`--psm 6`), especially around the cover image.

Detailed findings are in `docs/research/pdf-ocr-validation-2026-10-23.md`.

## Implemented workflow

`python -m dravidic_tts.pdf_batch` now:

1. detects unusable embedded PDF text;
2. renders and OCRs affected pages;
3. automatically repairs extracted text before speech;
4. groups the book into page-labelled parts of about 4,000 characters;
5. writes intermediate page text, part text, WAV files, a manifest, and a
   phone-friendly listening page under `outputs/pdf/`;
6. writes progress atomically and skips existing WAV files when restarted.

The neural image includes PDFium, Pillow, and Malayalam/English Tesseract. The
Dockerfile keeps large neural dependencies in an earlier cache layer so source
edits do not reinstall them.

## Operational commands

Check progress:

```powershell
docker logs --tail 50 dravidic-tts-pdf-worker
docker ps --filter "name=dravidic-tts"
```

If the worker stops before completion, remove only the stopped worker container
and launch the same Compose run again. Existing page text and WAV files are
reused:

```powershell
docker rm dravidic-tts-pdf-worker
docker compose --profile batch run -d --name dravidic-tts-pdf-worker pdf-worker
```

Restart only the listening server with:

```powershell
docker compose --profile batch up -d audio-server
```

## Remaining risks and next steps

occasional spelling errors, particularly on image-heavy pages. CPU synthesis
remains slow; the complete book can take many hours. After several parts are
ready, listen to the same short passage across the available Malayalam voices
and record exact chunk/word errors before changing acoustic models.
